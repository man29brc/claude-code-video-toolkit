# Weekly Social Planner

**Nothing is published or scheduled without the user's explicit approval of the final plan.**

## 1. Scope

Ask (in one message, only what's unknown):
- Which business(es) this week: WVS, CSC Balaji, UCF, or several? Plan each business separately, with each brand on its own accounts only.
- Which week (default: next Monday–Sunday) and time zone (default: Asia/Kolkata, IST).
- How many posts per business (default: 3–5), and what's already filmed or ready?
- Anything happening this week: offers, events, deadlines, festivals, campaigns?

Load each business's profile (offer, audience, language, tone, CTA) from memory, preferences, or project files. If missing, ask: what it offers and to whom, location and language, tone, and the call to action.

## 2. Pick the scheduling route

The user's preferred scheduler is **Social Post**. They have also used Buffer.

1. **Look for a connected scheduler tool.** Check the available tools/connectors for Social Post first, then Buffer or any other social scheduling connector (tools to list accounts/channels and create or schedule posts).
2. **Found one:** use it. Discover its accounts/channels, map each business to its accounts (confirm the mapping the first time and suggest saving it to memory), check the already-scheduled posts for that week to avoid double-booking and repeats, and check recent performance if the tool offers analytics.
3. **None connected:** say so in one line, and deliver a **copy-ready posting pack** (step 5b) the user can paste into Social Post or any app. Don't block on it.

Never guess a tool's parameters. Read each tool's description/schema before calling it.

## 3. Plan

Content mix per business per week (adjust to the post count):
- **Value / educate:** a tip, how-to, or common mistake
- **Proof:** a customer result, a behind-the-scenes look, or (for UCF) impact and a real story
- **Offer / ask:** the service CTA, or (for UCF) donate or volunteer
- **Timely:** a festival, local event, or deadline, if relevant

Posting times: default to evenings 7–9 PM IST and late mornings 11 AM–1 PM. Prefer times that analytics show work better.

## 4. Present for approval

```
**Week of <date> · <Business> · via <Social Post / Buffer / manual>**

| Day & time (IST) | Platform(s) | Type | Post idea | Media needed | Status |
|---|---|---|---|---|---|

**Captions**
1. <Day> — <full caption with CTA and hashtags>
...
```

Mark items needing media the user doesn't have yet as **"needs media"**. For Reel slots, offer to write the script (reel-script-writer skill).

Ask: "Approve all, or tell me what to change?"

## 5. After approval

**5a. With a connected scheduler:** create each approved post with the exact account/channel IDs the tool returned and the approved time. Save "needs media" items as drafts or ideas if the tool supports it, not as scheduled posts. Re-list the scheduled posts to verify, then report a short table (scheduled / drafted / failed, and why). If any call fails, stop, report what succeeded, and don't retry blindly.

**5b. Manual posting pack:** one block per post, in date order, so the user can copy-paste:

```
### <Day, date> · <time> IST · <Platform(s)> · <Business>
Media: <file / "needs media: <what to shoot>">
Caption:
<full caption, CTA, hashtags>
```

End with a checklist: `[ ] Mon 7 PM – WVS – Instagram` … for ticking off.

## Rules
- Never invent facts, prices, results, or testimonials. Use `[placeholder]`.
- Don't cross-post one business's content to another business's accounts.
- UCF: respectful, consent-aware storytelling. No exploitative imagery.
